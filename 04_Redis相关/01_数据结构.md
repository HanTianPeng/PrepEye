#### 01-五种数据结构
  - 字符串: 
    - `简单动态字符串(SDS)`: 二进制安全。
    - 最大是`512M`。
    - 缓存、Token、Session、计数器、分布式锁。
  - 列表: 
    - 3.2版本之前: `双向链表(LinkedList)`和`压缩列表(ZipList)`。
    - 3.2版本之后: `快速列表(QuickList)`。
    - 7.0版本之后: `紧凑列表(ListPack)`替代`压缩列表(ZipList)`。
    - 最终结论: `快速列表(QuickList)`和`紧凑列表(ListPack)`。
    - 消息队列、时间线、双端队列。
  - 集合: 
    -  `整数集合(IntSet)`和`哈希表(HashTable)`。
    - 好友去重、标签系统、点赞用户、共同好友、UV统计、自动去重。
  - 有序集合: 
    - 7.0版本之前: `压缩列表(ZipList)`和`跳跃表(SkipList) + 哈希表(HashTable)`。
    - 7.0版本之后: `紧凑列表(ListPack)`替代`压缩列表(ZipList)`。
    - 数据量少的时候，使用`紧凑列表(ListPack)`，避免`跳跃表(SkipList)`大量指针占内存问题。
    - `哈希表(HashTable)`解决了`member`进行查找问题: O(1)的`member`查找。
    - `跳跃表(SkipList)`解决了按`score`进行排序问题: TopN问题、排名查询、范围查询。
    - 排行榜、热搜榜、优先级队列、延迟队列。
  - 字典: 
    - 7.0版本之前: `压缩列表(ZipList)`和`哈希表(HashTable)`。
    - 7.0版本之后: `紧凑列表(ListPack)`替代`压缩列表(ZipList)`。
    - 用户信息、商品属性、配置对象；不适合超大字段、超多字段。

#### 02-底层实现原理(元素数量 + 元素大小 + 元素类型)
  - 双向链表(LinkedList): 解决插入、删除O(1)；指针占内存问题；
  - 压缩列表(ZipList): 无指针、连续存储、整数存储；连锁更新问题；`prevlen + encoding + data`，ZipList: `zlbytes + zltail + zllen + entry + entry+ ...`；
  - 紧凑列表(ListPack): 是`ZipList`升级版本，解决了连锁更新问题，中间插入、删除元素依然有问题，entry: `encoding + data + backlen`; ListPack: `total-bytes + count + entry + entry... + EOF`;
  - (QuickList): `ListPack` + `LinkedList`
  - 整数集合(IntSet): 有序整数数组，有序是为了实现二分查找，插入需要`realloc + memmove`问题 
  - 哈希表(HashTable): 查询快、插入快、删除快、去重方便；`链地址法`解决哈希冲突问题；`渐进式ReHash`
  - 跳跃表(SkipList): 本质是`多层链表`，不适用红黑树的原因: 实现简单、范围遍历友好、插入删除成本低

#### 03-Redis与Memcached的区别
  - `Memcached`是纯KV内存缓存数据库，`Redis`是数据结构内存缓存数据库。
  - `Memcached`不支持持久化。
  - `Memcached`是多线程内存模型，`Redis`核心命令是单线程内存模型。
  - `Memcached`是`Libevent`网络模型，`Redis`是`Reactor`网络模型。
  - `Memcached`是`Slab allocator`内存模型，`Redis`是`Jemalloc`内存模型。

#### 04-Pipeline的用处
  - 减少`RTT`次数，降低`网络I/O`，核心是降低网络往返成本。
  - 批量处理，但非事务
  - 大`Pipeline`会阻塞其他客户端，输出缓冲区暴涨等问题
  - `Redis Cluster`下的`Pipeline`不支持跨`slot`

#### 05-Redis如何实现大量数据插入？
  - 核心目标: 减少`RTT`，提高吞吐，避免阻塞单线程。
  - `Pipeline`批量发送命令
  - 多连接并发写入
  - `Redis Cluster`分片
  - 避免`BigKey`
  - 临时关闭`AOF FSYNC`
  - `redis-cli -c --pipe`批量导入(`-c`是针对于`Redis Cluster`的不能跨`slot`，这样可以自动`redirect`)，利用`RESP`协议，`Socket Streaming`。

#### 06-Redis的默认数据库数量如何修改?
  - `redis.conf`配置中的`databases 16`。
  - `Redis Cluster`不支持多数据库，只能使用`db0`。

#### 07-渐进式rehash
  - 为了解决hash冲突问题，`链地址法`也已经无法解决的时候，需要进行哈希键数量扩容；`load factor`太高(used/size)。
  - 每次`GET、SET、DEL、定时任务`进行迁移。
  - `fork时候需更保守(BGSAVE、BGREWRITEAOF)`，因为`rehash`会导致大量修改内存，`Copy-On-Write`的成本暴涨。
